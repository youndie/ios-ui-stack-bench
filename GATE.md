# GATE — RQ0, on the device

RQ0 asks whether every metric can be captured on a device without a paid account, and whether the
injected 50 ms stall is seen by both instruments in every arm. This file answers it for the iPhone XS,
the one device the study reads (BRIEF.md A1.7). It is written by
[B-06](docs/backlog/B-06-rq0-the-gate.md); the table below is generated by
`analysis/gate_reader.py` from `logs/b-06/` and is not edited by hand.

**How each control is recorded** (BRIEF.md A1.7, `harness/gate.py`):

| Metric | Control | Instruments, and how |
|---|---|---|
| Smoothness | a 50 ms main-thread stall every second, and the same path at 0 ms | Animation Hitches and the in-app frame logger, on a run where the app scrolls its own list, launched by `xctrace --launch` (Hitches cannot record beside the UI-test runner); the logger again on S2 through the harness |
| Startup | 200 ms held before "list populated", 5 launches with and 5 without, interleaved | App Launch with Points of Interest (`listPopulated` minus the first life-cycle interval), and the app's log (`listPopulated` minus process start) |
| Memory | 50 MiB allocated and written at launch, 3 launches with and 3 without | Activity Monitor's `memory-physical-footprint` of the app's process, and the app's `phys_footprint` samples |
| Size | 1 MiB of random bytes added to the device build | the zip proxy |

The pass conditions are in `analysis/gate_reader.py`'s header, committed before the first recording.
Nothing here compares arms: one control per metric per arm, and no figure below is a result about
A, B or C.

## Reading — 2026-10-11

**RQ0 is not green under the rule fixed before the recording, by one row.** B1's in-app startup
control came out above its 250 ms ceiling (the table below). The same launches pass when read
through App Launch, the instrument startup is read from (BRIEF.md A1.7). Both instruments pass for
every other arm. The delay is 200 ms, and every arm adds something on top of it, in both instruments:
blocking the main thread at launch also pushes back work scheduled after it, and the ceiling sat 50 ms
above the delay. The ceiling stays where it was set. The row is a failed cross-check of B1's in-app
startup figure, and it is printed beside every startup number that figure contributes to.

**Every other control passes in every arm**, C included:
- **The 50 ms stall is seen by both instruments in every arm**, and the 0 ms stall by neither. That
  includes C's Metal-layer frames, which the brief feared Animation Hitches might not see (its
  Risks; research §1.4): on the XS it sees them. Kill criterion 2 does not fire.
- **Every metric is captured for every arm** through free provisioning. Kill criterion 1 does not
  fire.
- **The memory and size controls** read about their known sizes in every arm and every instrument.
