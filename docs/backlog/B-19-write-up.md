# B-19 — The write-up

The brief's P4: one red / green / inconclusive verdict per RQ, regenerated from the CSVs, negative
results included; output under `docs/research/`.

- **The decision and its reason.** The results document starts from
  [docs/templates/results.md](../templates/results.md): the verdict table first, every number with a
  path into `logs/`, a same-device-same-session line under every table that draws from two items,
  retractions appended rather than edited away. RQs a kill criterion closed are reported "not
  measured" with the criterion that fired.
- The qualifications that can change the reading go before the verdicts: that S1 measures what
  Apple calls a warm launch, how C's frame rate on the 120 Hz device was configured, how the system
  chrome was handled in parity, and that the two devices run different iOS versions, so a
  difference between devices is not a difference between chips
  ([research](../research/research-architecture.md) §1.3, §1.6, §1.7, §1.2).
- RQ1's B − A and RQ5 are printed once per bridge arm, B1, B2 and B3, each with its own verdict
  word; there is no combined and no best-of verdict (amendment A1.1). S3 is descriptive (A1.2).
- The prior work of the brief's Context is compared with the results **as its sources report it**
  ([research §1.1](../research/research-architecture.md)), not as the brief summarises it.
- Before it is final, the brief's author reviews the verdict table against the frozen thresholds.

- AC: `docs/research/<date>-ios-ui-stack.md` (target), every number regenerated by a script from
  `logs/`, `make check` green.
- AC: the README's status line says what the results say, and links them.
- Anchors: `analysis/` (target), `logs/`.
